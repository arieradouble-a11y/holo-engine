# Дом 121-014: пилот детализации, 20.09.2026

Открыть `index.html` в браузере либо запустить из этой папки:

```powershell
py -m http.server 8766 --bind 127.0.0.1
```

Адрес: http://127.0.0.1:8766/ . «До / После» переключает дополнительные детали
в одной сцене, сохраняя ракурс. «Детали» приближает фасад и выключает потоки;
«Общий вид» возвращает дом целиком. Полностью исходная версия — `baseline.html`.
Переключатель «До» сравнивает геометрию при одинаковом выбранном качестве;
он не отменяет оптимизации движка пилота.

## Изменения

- Оконные откосы, выступающие отливы, дополнительные переплёты; накрывки и
  вертикальные стыки существующих наклонных ограждений лоджий; детали козырьков,
  ступеней и кровельного парапета. 3087 простых элементов, максимум 37 044 новых
  треугольника. Они объединены в 5 мешей и 2 набора линий, а не тысячи объектов.
- Два уровня геометрии. Базовые объёмные детали видны постоянно; мелкие детали
  включаются по экранному размеру окна, с гистерезисом. Геометрия заранее готова,
  при приближении она не пересоздаётся. В плане и разрезе дополнения скрыты.
- Обычный профиль: DPR до 1.25, свечение с половинным разрешением по каждой оси.
  Высокий: DPR до 1.75, полное разрешение свечения.
- Экономный: DPR до 1, без прохода свечения, отражения и экранного контура,
  ограничение 30 кадров/с. Оба уровня архитектурных деталей доступны.
- Авто начинает с экономного профиля на небольшом/сенсорном экране, с обычного
  на настольном; устойчивые задержки кадров могут понизить обычный до экономного.
  Автоматическое повышение намеренно отсутствует, ручной выбор доступен.
- В общем виде исключаются заведомо невидимые квартирные перегородки из
  обработки вершин. В плане, разрезе, разборке и при выборе интерьера сохраняется
  полный исходный набор линий. Нельзя переносить CPU-отсечение по этажам без
  отдельной проверки: граничная растеризация дала расхождения в эксперименте.

## Проверки

`qa/visual.json`: загрузка без ошибок, 1366×800 и мобильная раскладка 390×844,
переключатели, LOD в приближении, план, разрез и разборка. Кадры `qa/*.png`
сняты SwiftShader и не служат измерением скорости GPU.

`qa/invariants.json`: попиксельное сравнение с включённым/отключённым
исключением невидимой геометрии — ноль отличий во всех пяти режимах
(общий вид, план, разрез, разборка, выбранный интерьер). После прогрева обоих
LOD 20 переключений сохраняют 28 геометрий, без роста счётчика.

`qa/gpu.json`: настоящий ANGLE/D3D11 на **RTX 5080**, один браузер за раз.
Числа ниже — суммарные команды и примитивы всех проходов одного общего кадра,
не размер исходной модели. Включённые потоки одинаковы.

| Режим | Команд/кадр | Треугольников/кадр | Отрезков/кадр |
|---|---:|---:|---:|
| Исходник | 95 | 337 447 | 614 326 |
| Пилот, обычный | 106 | 393 931 | 587 722 |
| Пилот, экономный | 53 | 261 783 | 240 032 |

Экономный профиль уменьшает команды на 44%, треугольники на 22%, отрезки на 61%
относительно исходника. Это **не** утверждение о таком же проценте ускорения:
профили различаются эффектами. Обычная детализация повышает число команд и
треугольников; на этой видеокарте частота кадров упирается в частоту дисплея.
Мобильный viewport использует ту же RTX 5080, а не процессор телефона.
Фактический слабый ПК/телефон и нагрев длительной сессии ещё не проверены.

## Воспроизведение

Сборка требует только Node.js, без установки пакетов:

```powershell
node build-pilot.cjs
```

`source/` — снимок исходного viewer; `96-pilot.js` — модуль эксперимента;
`build-pilot.cjs` создаёт конфиг деталей и накладывает проверяемые изменения
на отдельную копию `engine/`. `engine/runtime.json` содержит уже имеющийся runtime.
Тесты `qa.cjs` и `verify.cjs` используют установленный Chrome и существующий
puppeteer-core канонического движка (пути указаны в начале файлов).

```powershell
node verify.cjs
node qa.cjs
node qa.cjs --gpu
```

Канонический движок, основной каталог и опубликованный сайт не изменены.

## Коррекция разборки

Разборка сверена с исходной «Панельной 9-этажкой (121 серия)». Направления
и величины разлёта общих систем совпадали; лишний отъезд создавал автоподбор
камеры для floorStudy, расширявший весь дом на максимальный сдвиг каждой системы.
На настольном экране восстановлены дистанция 13 вместо 24.83 и угол обзора 42°,
как у исходного экспоната. Переход из режима «Детали» сбрасывает его приближение.
На телефоне и в высокой узкой настольной вкладке используются реальные габариты
разнесённых систем; на настольном экране также учитывается правая панель.
Финальное поведение проверено в открытой вкладке Codex. Проверки и кадры: `qa/explode-comparison.json`,
`qa/explode-*.png`; воспроизведение: `node qa-explode.cjs`.
