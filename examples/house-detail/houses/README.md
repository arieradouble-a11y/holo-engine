# Детализация всех жилых голограмм — 20.09.2026

Локальный набор: 14 зданий, включая ранее согласованный `plan-121` и 13 новых.
Открыть http://127.0.0.1:8766/houses/ при сервере из родительской папки пилота.
В просмотрщике загружается только одно здание. Выпадающий список и стрелки
переключают дома; «До / После» сравнивает геометрию в одинаковом ракурсе и
профиле качества. «Детали» приближает фасад; «Общий вид» возвращает обзор.

## Геометрия

Новые откосы, отливы, профили окон, накрывки существующих балконных ограждений
и кромки козырьков/кровель привязаны к геометрии исходных моделей. Для кирпичных
домов глубже откосы; у современных домов тоньше профили. Сохраняются повороты
секций углового дома и ориентация проёмов внутреннего двора. Исходные стены,
планы, сети и проёмы не меняются. Малые размеры новых элементов условные, что
указано в карточках; это не обмеры исторических конструктивных узлов.

Дополнения объединены в 5–7 объектов на дом, включая линии. Треугольники
индексированы; мелкие профили включаются по экранному размеру окна с
гистерезисом. В планах и разрезах дополнения скрыты. Разборка использует
исходные направления каждой системы; детали едут вместе со своим фасадом,
кровлей или входом. Кадр крупных моделей рассчитывается по фактически
разнесённым частям; принятый настольный ракурс первого пилота сохранён.
У старых параметрических моделей общий вид дополнительно вписывается в
ширину телефона и узкой настольной панели; ручное приближение остаётся доступно.

## Производительность

Сохранены профили пилота: обычный DPR ≤ 1.25 и половинное разрешение свечения;
экономный DPR ≤ 1, без свечения/отражения/экранного контура, предел 30 кадров/с.
Авто выбирает экономный профиль для небольшого/сенсорного экрана и может
понизить качество при устойчивой перегрузке. LOD не пересоздаёт геометрию.

`qa/gpu.json` — измерение команд и примитивов всех проходов одного кадра
на RTX 5080, ANGLE/D3D11, 1366×800. Экономный профиль даёт примерно вдвое
меньше команд, на 34% меньше треугольников и на 58–59% меньше отрезков,
чем обычный профиль этой же детализированной модели. Это счётчики рендера,
а не обещание FPS на слабом телефоне: физические слабые устройства не проверены.

Обычный профиль добавляет 8–16 команд относительно варианта без новых
деталей. Прирост треугольников зависит от дома, до 56% у дома с двором;
экономный профиль уменьшает число проходов и разрешение. Поле
`originalEffectsWithoutDetails` в отчёте — эта же сцена без дополнений,
с восстановленными эффектами и DPR 2; остальные оптимизации пилота остаются,
поэтому это не отдельный замер полностью исходного движка.

## Проверки и воспроизведение

`qa/visual.json`: загрузка всех домов, корректные номера систем и координаты
деталей, совпадение смещений при разборке, скрытие в плане/разрезе, мобильный
размер 390×780. Кадры `qa/*-overview.png`, `*-close.png`, `*-before.png`,
`*-explode.png`, `*-plan.png`, `*-mobile.png` сняты программным SwiftShader:
они служат визуальной проверкой и не измеряют скорость видеокарты.
`qa/authoring.json` содержит размеры, матрицы проёмов и бюджет новых элементов.
`qa/framing.json` проверяет экранные границы исходных и новых вершин после
завершения разборки, а не только расчётную дистанцию камеры.
`qa/mobile.json` — отдельный окончательный прогон всех домов на 390×780
с ожиданием завершения вступительной анимации после смены мобильной эмуляции.

Из этой папки:

```powershell
node build.mjs
node qa.mjs
node qa.mjs --gpu
node qa.mjs --mobile-only
node qa-framing.mjs
```

Сборка использует локально установленный Three.js, тесты — puppeteer-core и
Chrome (пути в скриптах). Ничего устанавливать для просмотра готовых HTML
не требуется. `source/` — снимок движка принятого пилота, `source-configs/` —
снимок исходных 14 конфигураций. `build.mjs` повторяемо применяет изменения
к копии `engine/src/` и собирает отдельные HTML. Принятый `plan-121` берётся
из родительской папки пилота. Канонический проект `Desktop/3d/engine`
и опубликованный сайт этим набором не изменены.
