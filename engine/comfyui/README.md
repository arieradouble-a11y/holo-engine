# ComfyUI → голограмма: интеграция

Конвейер: **референс-картинка → ComfyUI (TRELLIS.2) → GLB на диске → `build.js` → голограмма**.

## Быстрый старт (драйвер, без MCP)

Рабочий путь — прямой драйвер `tools/image-to-3d.js` (zero-dep Node, HTTP API ComfyUI):

```bash
# 1. поднять ComfyUI (портативная сборка на Desktop):
#    Desktop\ComfyUI_cu128_50XX\ComfyUI_cu128_50XX\run_nvidia_gpu.bat
# 2. из папки engine:
node tools/image-to-3d.js --image "../Картинки/объект.jpg" --name kotel
# 3. результат: ../kotel.glb  →  дальше обычная сборка:
node build.js --config configs/kotel.json --model "../kotel.glb"
#    (или сразу: --config configs/kotel.json --build)
```

Драйвер сам: загружает картинку, конвертирует UI-воркфлоу в API-формат по
`/object_info`, включает вырезание фона для JPEG (`--no-rembg` — выключить),
подменяет отсутствующие attention-бэкенды, **упрощает меш** (см. ниже), ставит
префикс `holo_<имя>`, ждёт и скачивает GLB. Опции: `--faces N`, `--workflow`,
`--seed`, `--timeout`, `--out`, `--comfy`.

## Упрощение меша (`--faces`, по умолчанию 250000)

TRELLIS выдаёт 0.5–1 млн полигонов. Драйвер режет целевое число граней обоих
`Trellis2SimplifyMesh` (их `target_face_num` запитан от одного `PrimitiveInt`).
Ориентир по числу граней:
- **~250k (дефолт)** — округлые формы (колёса, цистерны) + чистая поверхность.
- ~90k — очень лёгкий файл, но техника с колёсами становится **гранёной**.
- ~350k — заметно круглее для сложных форм (проверено на КО-512: колёса гладкие).
- 1M (без --faces у авторского воркфлоу) — максимум детали, тяжелее файл.

«Ржавчину» скан-меша убирает **не** снижение полигонажа, а правки контурного
пасса (float-таргет + порог) — так что высокий полигонаж уже не грязнит.
Дальше движок ещё сваривает вершины и сглаживает (`smooth`).

## Мультивью — форма вернее (`--front/--back/--left/--right`)

С одного фото сеть **додумывает** невидимые части (зеркала, кабину, зад) →
кривовато. Мультивью даёт 4 ортогональных вида, и форма восстанавливается
**вернее**, т.к. сеть их видит. Нода `Trellis2ImageCondMultiViewGenerator`
принимает `front` (обязательный) + `back`/`left`/`right` (опц.).

```bash
# А) лист 2×2 одной картинкой — авто-нарезка (рекомендуется):
node tools/image-to-3d.js --sheet sheet.png --name obj --faces 300000 --out "../obj.glb"
#    квадранты: верх=перёд|зад, низ=левый|правый борт

# Б) 4 отдельных вида (перёд/зад/левый борт/правый борт):
node tools/image-to-3d.js --front f.png --back b.png --left l.png --right r.png \
     --name obj --faces 300000 --out "../obj.glb"
```

Как готовить виды: сгенерить в image-модели **один лист 2×2** (перёд/зад/лев/прав)
на однотонном светлом фоне, без подписей/размеров/палитры, ортогонально. Дальше
**`--sheet` режет сам**: драйвер читает размеры листа из PNG/JPEG-заголовка
(zero-dep), загружает его один раз и вставляет в граф ноды `ImageCrop` по
квадрантам (LoadImage→ImageCrop→PreProcess). Никакого внешнего питона/PIL.
Драйвер также достраивает недостающие цепочки `left/right` по образцу переднего
вида и включает rembg на всех.
Проверено: ассенизационная из 4 видов → GLB 5.6 МБ, 167k верт., 176 с; кабина/
зеркала/зад восстановлены. Дефолт-воркфлоу `MeshOnly_MultiView.ui.json`.
Потолок всё равно нейро-меш — не CAD-уровень авторской модели.

## ВАЖНО: бэкенды внимания на RTX 50XX (Blackwell)

- `flash_attn` под Windows-портативку не собран → полное внимание переводится
  на **sdpa** (нативный torch, работает).
- `xformers` на Blackwell **роняет CUDA намертво** (внутри зовёт Hopper-ядра
  flash-attention: `invalid argument`) — не использовать.
- Sparse-код TRELLIS.2 умеет sdpa из коробки (фолбэк-ветка), но в combo ноды
  его не было — **мы добавили `"sdpa"`** в `nodes.py` строка ~348:
  `"sparse_backend": (["xformers","flash_attn","sdpa"], …)`.
  ⚠ Патч затрётся при обновлении ноды ComfyUI-Trellis2 — повторить одной строкой.
- Драйвер подменяет оба бэкенда на sdpa автоматически.

## VRAM (16 ГБ): что влезает

- **Дефолт драйвера — `MeshOnly_HighQuality_NoCascade`** (база 1024, без
  HR-каскада): HR-этап 1536³ на sdpa не помещается в 16 ГБ и убивает сервер.
- Перед генерацией **освободите GPU**: локальный llama-server (`-ngl 99` ≈ 13 ГБ)
  или другие CUDA-процессы не оставляют TRELLIS места — проверka: `nvidia-smi`.
- Если всё равно тесно: воркфлоу `MeshOnly.json` (база 512) или FP8-веса
  (`visualbruno/TRELLIS.2-4B-FP8` в ноде LoadModel; потребует докачки).

**Полный проход подтверждён** (RTX 5080, свободная VRAM): фото → GLB 18 МБ за
≈9 минут одной командой; повторный прогон — тоже успешен. Особенность ноды
Trellis2ExportMesh: она пишет `<префикс>_00001_.glb` на диск, **не сообщая файл
в history** — драйвер добирает результат перебором счётчика через `/view`
(старший индекс = новейший). Демо: `Илосос из фото (голограмма).html`
(конфиг `configs/ilosos-foto.json`). xformers 0.0.32.post2 установлен в
python_embeded, но не используется (оставлен на будущее).

## 0. Что нужно на стороне ComfyUI

- Рабочий **ComfyUI** (по умолчанию `http://127.0.0.1:8188`).
- 3D-ноды под задачу:
  - **whole/scan** (один слитный меш, отличное качество): `ComfyUI-TRELLIS2`
    (веса Microsoft TRELLIS.2).
  - **structured/разборка на части**: `ComfyUI_PartPacker`
    (веса `nvidia/PartPacker` + `facebook/dinov2`), ≤12 ГБ VRAM с `cpu_offload=true`.
    Либо **PartCrafter** отдельным репозиторием (ноды ComfyUI пока нет).

```bash
claude mcp add --transport http comfyui http://127.0.0.1:9000/mcp
```
или скопировать блок `mcpServers` из [`mcp.json`](mcp.json) в корневой `.mcp.json` проекта.
> Пока сервер не поднят — Claude Code будет показывать ошибку подключения к `comfyui`. Это ожидаемо.

## 3. Добавить workflow

1. В ComfyUI соберите граф (TRELLIS.2 или PartPacker) и проверьте, что он генерит на своём эталонном изображении.
2. **Save (API Format)** → положите JSON в папку `workflows/` сервера.
3. В JSON: вход изображения замените на строку **`PARAM_IMAGE`**; нода сохранения должна писать **`.glb` в `output/`** с предсказуемым именем.
4. Имя файла-графа = имя инструмента (`trellis2.json` → инструмент `trellis2`).

Ориентир по структуре — [`image-to-3d.workflow.template.json`](image-to-3d.workflow.template.json)
(это **заглушка**, `class_type` в ней выдуманные — замените своим экспортом).

## 4. Сборка голограммы из результата

**Вариант А — whole/scan (TRELLIS.2, один GLB):**
```bash
node build.js --config configs/<имя>.json --model "../output/holo_out.glb" \
              --out "../<Название> (голограмма).html"
```
Конфиг — как `configs/ilosos.json` (`"mode": "whole"`, `parts: []`, можно `markers`).

**Вариант Б — structured/разборка (PartPacker/PartCrafter, папка частей):**
Сохраните части как отдельные `*.glb` в одну папку (PartPacker: «path saving»), затем:
```bash
node build.js --config configs/<имя>.json --parts "../output/parts_dir" \
              --out "../<Название> (голограмма).html"
```
Режим `--parts` (реализован в `build.js`):
- встраивает по одному ассету на файл, ключи `part00, part01, …`;
- каждый меш тегируется своим ключом → существующий `matRules`/`matToPart` делит на системы;
- авто-заполняет `mode:"structured"`, `parts[]` и `matRules[]`, **если их нет в конфиге**
  (файлы сортируются по имени → назовите их `01_kotel.glb`, `02_gorelka.glb`, … для нужного порядка).
- Чтобы задать русские названия/теги/цвета и «горячие» узлы — пропишите `parts`/`matRules`/`hotParts` в конфиге вручную (тогда авто-заполнение не сработает).

Проверено: 2 GLB → 2 системы, structured-режим, select/explode работают, ошибок нет.

## 5. Честные ограничения (важно)

- **TRELLIS.2 = один слитный меш.** Даёт только whole/scan — без чистой разборки на узлы.
- **Part-aware (PartPacker/PartCrafter/OmniPart)** делит на **геометрические** части
  («верх/низ/выступ»), а не на инженерные системы («котёл / газоход / насос»).
  Оборудование ЖКХ для этих моделей — вне обучающего распределения, поэтому качество разбивки
  на нашем классе объектов **надо проверять** (начните с demo PartCrafter на HuggingFace — без установки).
- Импортный меш почти всегда требует правки масштаба/ориентации (движок нормализует размер,
  но не «поставит на пол» кривую ось) и чистки. Часто нужен ретопологический/decimation-проход.

## 6. Резервный путь (самый предсказуемый по качеству)

Генерить **каждый агрегат отдельно** (TRELLIS.2: котёл, насос, бак, теплообменник),
складывать `*.glb` в папку и собирать через `--parts`. Разбивка на системы тогда под нашим
контролем (один файл = один узел), а не на удачу нейросети. Это де-факто «GLB-версия» того,
что процедурная котельная делает из примитивов.
