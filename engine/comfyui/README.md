# ComfyUI → голограмма: интеграция (скелет)

Конвейер: **референс-картинка → ComfyUI (TRELLIS.2 / PartPacker) → GLB на диске → `build.js` → голограмма**.

MCP-сервер служит «спусковым крючком» (запустить граф, дождаться, узнать имя файла).
Сам `.glb` Claude Code читает **прямо с диска** (всё локально) и передаёт в сборщик.

---

## 0. Что нужно на стороне ComfyUI

- Рабочий **ComfyUI** (по умолчанию `http://127.0.0.1:8188`).
- 3D-ноды под задачу:
  - **whole/scan** (один слитный меш, отличное качество): `ComfyUI-TRELLIS2`
    (веса Microsoft TRELLIS.2).
  - **structured/разборка на части**: `ComfyUI_PartPacker`
    (веса `nvidia/PartPacker` + `facebook/dinov2`), ≤12 ГБ VRAM с `cpu_offload=true`.
    Либо **PartCrafter** отдельным репозиторием (ноды ComfyUI пока нет).

## 1. MCP-сервер (joenorton/comfyui-mcp-server)

```bash
git clone https://github.com/joenorton/comfyui-mcp-server
cd comfyui-mcp-server && pip install -r requirements.txt
# указать свой ComfyUI при необходимости и запустить (поднимет http://127.0.0.1:9000/mcp)
python server.py
```

## 2. Подключить к Claude Code (когда сервер уже запущен)

Одной командой:
```bash
claude mcp add --transport http comfyui http://127.0.0.1:9000/mcp
```
или скопировать блок `mcpServers` из [`mcp.json`](mcp.json) в корневой `.mcp.json` проекта.
> Пока сервер не поднят — Claude Code будет показывать ошибку подключения к `comfyui`. Это ожидаемо.

## 3. Добавить workflow

1. В ComfyUI соберите граф (TRELLIS.2 или PartPacker) и проверьте, что он генерит на своём эталонном изображении.
2. **Save (API Format)** → положите JSON в папку `workflows/` сервера.
3. В JSON: вход изображения замените на строку **`PARAM_IMAGE`**; нода сохранения должна писать **`.glb` в `output/`** с предсказуемым именем.
4. Имя файла-графа = имя инструмента (`trellis2.json` → инструмент `trellis2`).

Ориентир по структуре — [`image-to-3d.workflow.template.json`](image-to-3d.workflow.template.json)
(это **заглушка**, `class_type` в ней выдуманные — замените своим экспортом).

## 4. Сборка голограммы из результата

**Вариант А — whole/scan (TRELLIS.2, один GLB):**
```bash
node build.js --config configs/<имя>.json --model "../output/holo_out.glb" \
              --out "../<Название> (голограмма).html"
```
Конфиг — как `configs/ilosos.json` (`"mode": "whole"`, `parts: []`, можно `markers`).

**Вариант Б — structured/разборка (PartPacker/PartCrafter, папка частей):**
Сохраните части как отдельные `*.glb` в одну папку (PartPacker: «path saving»), затем:
```bash
node build.js --config configs/<имя>.json --parts "../output/parts_dir" \
              --out "../<Название> (голограмма).html"
```
Режим `--parts` (реализован в `build.js`):
- встраивает по одному ассету на файл, ключи `part00, part01, …`;
- каждый меш тегируется своим ключом → существующий `matRules`/`matToPart` делит на системы;
- авто-заполняет `mode:"structured"`, `parts[]` и `matRules[]`, **если их нет в конфиге**
  (файлы сортируются по имени → назовите их `01_kotel.glb`, `02_gorelka.glb`, … для нужного порядка).
- Чтобы задать русские названия/теги/цвета и «горячие» узлы — пропишите `parts`/`matRules`/`hotParts` в конфиге вручную (тогда авто-заполнение не сработает).

Проверено: 2 GLB → 2 системы, structured-режим, select/explode работают, ошибок нет.

## 5. Честные ограничения (важно)

- **TRELLIS.2 = один слитный меш.** Даёт только whole/scan — без чистой разборки на узлы.
- **Part-aware (PartPacker/PartCrafter/OmniPart)** делит на **геометрические** части
  («верх/низ/выступ»), а не на инженерные системы («котёл / газоход / насос»).
  Оборудование ЖКХ для этих моделей — вне обучающего распределения, поэтому качество разбивки
  на нашем классе объектов **надо проверять** (начните с demo PartCrafter на HuggingFace — без установки).
- Импортный меш почти всегда требует правки масштаба/ориентации (движок нормализует размер,
  но не «поставит на пол» кривую ось) и чистки. Часто нужен ретопологический/decimation-проход.

## 6. Резервный путь (самый предсказуемый по качеству)

Генерить **каждый агрегат отдельно** (TRELLIS.2: котёл, насос, бак, теплообменник),
складывать `*.glb` в папку и собирать через `--parts`. Разбивка на системы тогда под нашим
контролем (один файл = один узел), а не на удачу нейросети. Это де-факто «GLB-версия» того,
что процедурная котельная делает из примитивов.
